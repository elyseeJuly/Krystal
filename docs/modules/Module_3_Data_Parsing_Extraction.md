## 模块三：数据通道与解析协议 (Data Parsing & Extraction)
前端解析 `.krys` 文件时，不能仅依赖纯视觉或纯隐写，必须实现一套具备强鲁棒性的**明暗双轨制 (Dual-Track Parsing)**，并结合“锚点解析”以解决跨模型视觉读取偏差。

### 3.1 明暗双轨制优先级逻辑
为了对抗社交软件（如微信、微博）的图片压缩导致的视觉数据损毁，前端读取必须遵循双轨容错机制：
*   **暗轨 (Steganography / Payload) [最高优先级]**：读取 `.krys` 文件底层 100% 无损的 JSON 数据。前端优先尝试通过 LSB（最低有效位隐写）、EXIF/PNG Chunk 读取，或解析类似 Zip 容器结构的文件（提取 `full_payload.bin`）。
*   **明轨 (Visual Lattice) [降级优先级]**：当暗轨数据丢失（例如仅剩手机截图）时，启用视觉提取。前端通过大模型视觉能力读取图像边缘的文字、语义图案 (Glyph) 与低密度金丝编码，目标是至少恢复 70% 的核心逻辑以维持基础运转。

### 3.2 显式文本锚点 (Anchor-based Parsing)
由于大模型在视觉扫描时不会严格按照顺时针顺序读取，而是依赖概率集合跳读，前端在生成或解析明轨晶面时，**禁止仅依赖边框位置**，必须引入显式文本锚点：
*   **解析规则**：前端编译器 (Xtal-Compiler) 在渲染六晶面时，必须在对应区域强制写入 `[INPUT]`、`[LOGIC]`、`[OUTPUT]` 等大写文本关键词。
*   **降维提取**：当视觉紊乱时，AI 或前端解析器通过全局搜索这些文本锚点，提取其后的内容，从而实现“空间结构 + 文本锚点”的双重驱动。

### 3.3 晶核指纹校验 (Crystal Fingerprint)
为防范恶意篡改，前端必须在“左上棱 (Correction Facet)”的载荷中读取并校验 SHA-256 哈希值。
*   **校验公式**：`Hash(视觉像素数据 + 底层JSON载荷 + 带隙色值)`。
*   **拦截逻辑**：若前端计算出的哈希值与暗轨内嵌的哈希值不匹配（例如：黑客将高危的红带隙 P 成了安全的绿带隙），前端必须立刻抛出**“晶格失配 (Lattice Mismatch)”**的严重告警，并中断常规执行流程。
