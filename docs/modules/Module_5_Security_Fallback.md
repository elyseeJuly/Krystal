## 模块五：安全防线与离线降级策略 (Security & Fallback)
KIP 协议的核心优势是抗审查与离线可用，前端必须建立一套去中心化的安全防护网和断网降级策略。

### 5.1 带隙 (Band Gap) 权限阻断机制
带隙不仅是视觉元素，更是前端**机器可读的权限触发器**。前端必须根据读取到的安全等级执行严格的 UI 阻断：
*   🟢 **绿色 (Safe)**：纯文本/本地逻辑，直接静默折射。
*   🟡 **黄色 (Caution)**：包含外部 API (Inclusion)，前端需弹窗提示外部网络请求。
*   🔴 **红色 (Restricted)**：系统级或高危权限。前端**必须**在折射前阻断，并强制输出二次确认提示：`“⚠️ 此晶体请求高危权限，确认继续？[Y/N]”`。

### 5.2 离线优先原则与晶级降级 (Offline Fallback)
为了彻底摆脱大厂的云端 API 依赖（防范“拥抱-扩展-熄灭”策略），前端在解析晶体时需遵循强制的“自包含”要求：
*   **1 晶级 & 2 晶级执行**：此类 `.krys` 文件必须 100% 自包含所有逻辑。前端在无网状态下，只要连接了本地运行的轻量级多模态模型，就必须保证其能够被完整解晶与执行。
*   **3 晶级执行 (含外部包裹体 Inclusion)**：允许调用外部 API 或云端知识库。但前端解析器在检测到断网时，必须能够读取文件内的“容错冗余代码”（位于 Correction Facet），提供无外部依赖的纯本地降级运行方案，不允许直接白屏或死机。

### 5.3 晶核审计 (Core Audit) 拦截
前端的解析器应当接入“恶意晶体黑名单”机制。对于包含诈骗、越狱或隐私窃取的晶体，前端应当在 `Xtal-Validator` 校验阶段直接拒绝解晶（即拒绝色散），并向用户抛出极高危的安全告警。
